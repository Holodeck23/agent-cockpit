# Architecture

Cockpit is a local Node server that drives the agent CLIs, a React page that talks to it, and an Electron shell that puts the page in a native window. The server is the product; the page and the app are views of it.

```
┌──────────────── Cockpit.app (Electron) ─────────────────┐
│ main process                                             │
│   window key ── added to the Cockpit window's /api calls │
│   server/start.ts  HTTP + SSE on 127.0.0.1:<random>      │◄── page (sandboxed, no Node)
│     threads/manager ──► agents/claude      (claude -p)   │
│                     ├─► agents/codex       (app-server)  │
│                     ├─► agents/antigravity (agy)         │
│                     └─► agents/acp         (opencode acp)│
│     processes/runner ─► dev servers (process groups)     │
│     http/mcp-routes  ◄── cockpit MCP (one per agent      │
│                          session, over HTTP + token)     │
│     remote/service   ◄── phone listener (tailscale serve)│
│     remote/preview   ◄── one listener per phone-preview  │
│     browser pages    ── in-app browser (WebContentsView) │
└──────────────────────────────────────────────────────────┘
          <state> = COCKPIT_HOME, or ~/.agent-cockpit
          <state>/threads/<id>/{meta.json, events.jsonl, messages.md}
          <state>/attachments/<id>/   images sent and received
          <state>/{projects,workflows,memory,presets,remote,push,phone-previews,processes}.json
          <state>/agent-operations/   logs of CLI installs, updates and sign-ins
          <state>/logs/main-errors.log   errors the crash guard kept running through
```

## Layout

| Path | Role |
|---|---|
| `server/agents/` | One adapter per CLI (`claude`, `codex`, `antigravity`, and `acp` for OpenCode). Each turns its wire protocol into `NormalizedEvent` (`types.ts`). `stop.ts` is the shared EOF, SIGTERM, SIGKILL ladder; `stdin.ts` keeps a closed agent pipe from throwing. |
| `server/threads/` | The thread store (files), the manager (live sessions, statuses, approvals, agent switch) and the handoff builder. |
| `server/processes/` | The process runner: long-running project commands, their output buffers and group shutdown. |
| `server/mcp/` | The cockpit MCP server (runs as its own process per session), its tools, session tokens and per-CLI wiring. |
| `server/http/` | The API: loopback guard, JSON helpers, routes for threads, projects, processes and MCP callbacks, and the SSE stream. |
| `server/remote/` | Tailscale listener, identity guard, paired-device store, encrypted Web Push subscriptions and approval notifications. `routes.ts` classifies every API route as allowed on the phone or not. |
| `server/remote/preview/` | Phone live preview: the slot store (`phone-previews.json`), one-use tickets and sessions (`access.ts`), per-app listeners and the proxy to the dev server (`gateway.ts`), and the Mac's control routes (`control.ts`). |
| `server/agents/capabilities/`, `server/agents/lifecycle/` | What each CLI really supports (identity-keyed records, probes) and the install, update and sign-in plans, with pinned official installers. |
| `server/browser/` | The rules for agents driving the in-app browser: origin classes, per-run grants and strict tool inputs. Electron owns the pages themselves. |
| `server/results/`, `server/runs/`, `server/git/` | Result cards, host checks and their receipts; before and after workspace observations; branch, change and diff reading. |
| `server/onboarding/`, `server/import/`, `server/memory/`, `server/presets/` | The first-run director and recovery, importing CLI sessions, cross-conversation memory, and agent presets. |
| `server/workflows/` | Saved instructions, prompt expansion and schedules while the app is running. |
| `server/files/` | Bounded project file access and attachment expansion. |
| `server/projects/` | `projects.json`: pinned projects, names and colours. |
| `web/src/` | The React UI. `useCockpit.ts` holds page state fed by one SSE stream; `transcript.ts` turns raw events into what the thread view draws. |
| `electron/` | Main process (window, menu, quit handling, update check, Dock activity), the window key (`window-key.ts`), the in-app browser (`browser-service.ts`, `browser-policy.ts`, `browser-agent-host.ts`), the crash guard (`crash-guard.ts`), the preload bridge and login-shell PATH (`shell-path.ts`). |
| `scripts/` | Build, smoke tests against real CLIs, and proof gates that drive the packaged app. |

## Decisions and why

**Drive the official CLIs instead of calling model APIs.** The point is to use subscriptions already paid for, with each CLI's own tools, permissions and sessions. The cost is tracking two undocumented-in-places wire protocols, which [PROTOCOLS.md](PROTOCOLS.md) records.

**One event model.** Adapters normalize everything into a small union (session, text, tool use and result, approval request and resolution, usage, result, exit, error). Storage, statuses, the transcript and the UI are written once against that, which is what made adding Codex and switching agents mid-thread cheap.

**Files first.** A thread is `meta.json`, an append-only `events.jsonl` and a human-readable `messages.md`. Nothing needs a database, a thread survives a restart, and the transcript is a file an agent (or you) can read. Status is derived from the event log, not stored. Because one damaged conversation must not hide the rest (the list reads them all), reads are tolerant. A line that does not parse as an event (half a line after a crash, a power cut or a full disk) is skipped. A `meta.json` that does not parse leaves its conversation out of the list. Each case is reported once, and the file is never rewritten. Every append first checks for a missing final newline (one byte), so a new event never joins a half line. Reads are incremental: the store keeps each conversation's parsed events and parses only the bytes appended since, stopping at the last newline, so status and the list no longer re-read whole logs, and a streamed token reuses the conversation's last status. Every JSON store writes atomically through a random temp name created exclusively, and the state folder is kept at 0700.

**Electron around the existing server.** Tauri would have needed a bundled Node sidecar or a Rust rewrite of a proven backend; Electron runs `server/*` unchanged in its main process. The page still talks HTTP and SSE, exactly as in a browser, which also supports the paired phone view.

**Security model.** Anything on the machine can reach 127.0.0.1, including a web page in a browser. The guard (`server/http/guard.ts`) requires a loopback Host (against DNS rebinding), a matching Origin when present (against CSRF), and `application/json` on writes (which forces a CORS preflight the server never answers). The page runs with `contextIsolation`, `sandbox` and no Node. The preload bridge (`electron/preload.ts`) is the page's only native surface: native folder and new-project panels, theme, clipboard, notifications, Dock activity, the preview pane, and opening, revealing, trashing or copying in files of a project Cockpit already lists. The preload bridge also carries the in-app browser's controls. The main process checks every call's sender origin and re-checks paths against the known projects and the thread folder. Opening a file of a type macOS runs or installs (`.command`, `.terminal`, `.app`, scripts, `.pkg`…), or any executable file, shows a native confirmation with the real name first. Every file name the page shows makes reordering, zero-width and control characters visible as `⟨U+202E⟩` (`server/files/visible-name.ts`), so `Invoice-<U+202E>fdp.command` cannot pass for a PDF. Every CLI flag comes from a schema allowlist.

**The in-app browser.** Since wave 9 the desktop app shows previews and reply links in a host-drawn page (a sandboxed `WebContentsView` with no preload) placed over the pane, one page per conversation. Website data lives in a persistent partition per workspace folder, named by a hash, never in the control session or another workspace's. `isAllowedRequest` and `isNavigable` (`electron/browser-policy.ts`) let web traffic and the person's own dev servers pass and refuse Cockpit's listener ports, `file:` and privileged schemes, on every request, redirect and navigation. At most eight pages stay loaded and idle ones are unloaded after about five minutes. The agent's browser tools (`server/browser/agent.ts`) derive the page, the run and the workspace from the session grant, never from the request. Reading a local page asks nothing. Reading or navigating to a remote site asks, and every input action asks on any site. A grant names one run and one exact origin, and a Deny, Stop, timeout or closed page removes it. Typed text is redacted before an event is stored.

**What the page may load.** The page renders text agents and repositories write. React escapes it, and the page is served with a Content-Security-Policy as a second line of defence (`PAGE_POLICY` in `server/start.ts`): scripts, styles, images and connections come from Cockpit only, frames only from local previews, and nothing may frame Cockpit. A Markdown document with `![](https://…)` therefore cannot beacon out or reach the LAN. Reply links show their destination as a tooltip, and the real host beside them when their text names another site. Git is run with `core.fsmonitor=` on the command line, because Cockpit runs `git status` as soon as a folder opens and a repository's own `.git/config` could otherwise name a program to run.

**The window key.** The guard stops web pages, not other programs: any local process, an agent's shell included, can send any Host, Origin and Content-Type. So the desktop app makes a random key at each launch and requires it on every `/api` request except `/api/mcp`, which has its own session tokens. The main process adds the header in `onBeforeSendHeaders`, and only for requests from the main window's own top frame while it shows Cockpit's page. The preview iframe and the hidden capture window never get it, and a page-supplied value is stripped. A preview or capture can never open Cockpit's own ports: that page in the preview frame (sandboxed with `allow-same-origin` for ordinary dev servers) would share the keyed window's origin. The key exists only in main-process memory: not in env, argv, a file or the preload. Without it an agent could approve its own approval requests over HTTP. `npm start` runs without a key and warns that any local program can use its API.

**Phone access is a second listener, not a loosened guard.** The desktop listener keeps its random port and loopback guard. Phone access adds a listener on a fixed 127.0.0.1 port (47821) that only `tailscale serve` reaches, proxying `https://<mac>.<tailnet>.ts.net`. Tailscale passes the original Host through, sets `X-Forwarded-Proto: https`, and replaces any client-sent `Tailscale-User-*` headers with the requester's tailnet identity (verified in its source, `ipn/ipnlocal/serve.go`, and live). The phone guard (`server/remote/guard.ts`) requires the loopback socket, the tailnet Host, HTTPS, a login on the allowlist (by default the Mac owner's), a matching Origin, and JSON writes. After that, each phone needs a pairing cookie approved on the Mac: a random token stored only as a SHA-256 hash, bound to the login that paired it, revocable from the Phone panel. The phone can read conversations, reply, answer approvals and stop a turn; opening folders, reading project files, editing workflows, controlling processes and changing settings are refused. Revoking a phone also ends the live stream it has open. The phone's own page may POST only to the control origin and the preview origins (`form-action` in the page policy). Asking to pair again with the same name replaces the earlier request rather than handing back its id (the redemption secret), and pending requests are capped per login. A local process could forge the Tailscale headers by calling the port directly, but it can already call the desktop API, so that grants nothing new.

**Phone live preview.** A paired phone can open a running dev server on its own origin: an app gets a slot, an HTTPS port from 8443 to 8458 on the tailnet name in front of its own loopback listener from 47822 to 47837. A slot is a folder, a name and a hash of the exact command Cockpit started. Slots are persisted and never reused, even when the app stops or its project is removed, so a phone tab that is still open cannot script a different app on the same origin. The Mac shows the exact `tailscale serve` command and runs it only on a click, and it never takes over a port that already serves something else. The phone asks the control origin for a ticket for one process (random, one-use, 30 seconds, bound to the phone, its login, the app, the process id and the origin) and posts it from a form to the app's own origin, which consumes it and opens a session (30 idle minutes). Each phone and app keeps a cookie jar in memory, so the app's sign-in survives a re-open. A stop, exit or restart is a new process generation and ends the old sessions and sockets. Removing a phone, turning phone access off, removing the project and quitting also end access. Turning phone access off leaves the preview `tailscale serve` entries as they are. Requests are capped at 10 MB, and a preview refuses writes from another origin.

**Phone notifications.** `server/remote/push.ts` stores VAPID signing keys and paired-phone subscriptions in `push.json` under the private state directory, with mode 0600. A live approval request sends the project name, conversation title and id encrypted through Web Push. A subscription's endpoint must belong to a browser push service (Apple, Google FCM, Mozilla, Microsoft), checked when a phone registers and again before each send: otherwise a paired phone could make the Mac post to any address, loopback and LAN included. Sending is gated on phone access running and the device remaining paired. Revocation removes subscriptions; normal delivery removes expired endpoints on HTTP 404/410. Push requests use a 15-second socket timeout. The phone registers `web/public/sw.js`, waits for activation and reconciles browser subscription state with the Mac. A notification tap opens `/?thread=<id>`. Payloads can appear on the phone lock screen. Tests verify the server flow using an injected sender; physical-device delivery and tapping remain separate acceptance checks.

**Handoff is shown before it is sent.** Switching agents starts the new session with a transcript built by `server/threads/handoff.ts`. Before the switch the picker asks `GET /api/threads/:id/handoff` and shows that exact text, its size and how many earlier messages were left out to fit a 400,000-character budget (the opening request and the newest messages are kept, never half a message). Starting the handoff sends the text's sha256 back with `POST /api/threads/:id/agent`. If the conversation changed meanwhile the switch is refused, so the agent only receives what the person saw.

**Agent CLIs are managed, but only on request.** `server/agents/lifecycle/` installs, updates and signs in with fixed executable and argument lists, never assembled from agent output, never with `sudo`. Installers are fetched from the vendor's own hosts and compared with a hash pinned in `plans.ts`. A changed script is not run until a person approves the new hash (`npm run check:installers` re-reviews them before every release). An update waits for the CLI's idle sessions and holds new ones. These routes are refused on the phone and never exposed through MCP.

**The main process does not freeze on an error.** The server runs in Electron's main process, where an uncaught error normally shows a modal dialog that blocks the window, the phone and every agent session. `electron/crash-guard.ts` records each error with its stack in `<state>/logs/main-errors.log` (a log over 1 MB moves to `.1`) and keeps Cockpit running. It hides nothing.

**Hooks off by default.** Your own Claude Code hooks merge into every session, and SessionStart hooks can hijack a headless run. Cockpit threads set `disableAllHooks` unless the thread opts in.

**Agent pipes never take the server down.** The server runs in Electron's main process beside every other conversation, so one agent's failure must stay in its conversation. A CLI that exits or closes stdin still looks writable until Node handles its exit, and the next write fails asynchronously with EPIPE. Every adapter attaches an error handler to the agent's stdin (`agents/stdin.ts`): the lost write becomes an error event in that conversation, and the exit handler ends the session as usual. The line parsers and JSON-RPC handlers are guarded too, so an odd message becomes an error in that conversation. A write that fails (a full disk) loses that event from the log, but the conversation's state still moves on: a lost result or exit still ends the turn and releases the session. Agents run as their own process group, so a CLI that must be terminated or killed takes the shell commands it started with it; one that exits on EOF tidies up after itself.

**Processes as groups.** `npm run dev` forks: sh, npm, node, a bundler. Killing only the direct child leaves the server holding its port. Each process is spawned `detached` as its own group and stopped as a group (SIGTERM, then SIGKILL after 3 s). Output is split into numbered lines, stripped of terminal codes, capped at 512 KB, and scanned for the first local URL.

**The cockpit MCP talks back over HTTP with a session token.** The MCP server is a separate process the CLI spawns, so it needs a way home. It gets the server URL and a token through its environment. The token is about identity and scope, not secrecy: a session's tools see only that session's project, and stop working when the session ends. It is never on a command line: Claude passes its environment to MCP servers, and Codex forwards named variables through `env_vars`. It cannot be kept from the agent itself: the agent's shell runs as the same user and inherits the CLI's environment. So the CLI's own approval prompt is never what protects a change. Every MCP route that changes something asks on the server (next paragraph), and the CLIs pre-approve those tools so nothing asks twice.

**Cheap tools don't ask, costly ones do, and Cockpit is the one asking.** Listing, reading logs, recall, reading conversations, opening a localhost preview and capturing its screenshot are pre-allowed. The browser tools follow their own rule (above). `open_preview` sends the loopback URL to a resizable iframe in the sandboxed page. `inspect_preview` uses a short-lived sandboxed Chromium window in its own in-memory session, cleared after every capture, so an agent cannot screenshot a local app as you are signed in to it. It returns a normalized 1280×800 PNG. Both reject non-loopback targets and Cockpit's own ports; neither can navigate to a remote origin.

Starting or stopping a process, `remember`, `save_workflow` and the conversation controls are approved by Cockpit on the server (`threads/host-actions.ts`), with the same card as a shell command and a 45-second window. Processes offer Allow for this session, until the agent session ends. A memory for every project says so on the card. `save_workflow` skips the card only when the project lets agents manage workflows. Even then, an agent's update to a workflow that runs with more than manual or plan permissions, or with hooks, pauses its schedule until you turn it back on. Agent-written titles on a card stay on one line. The card shows the request whole: array commands quoted and never cut, risk badges for options such as running outside the sandbox, all input behind a disclosure, and a capped detail that scrolls from its top, so padding cannot push a command's start away from Allow.

**Quit leaves nothing behind.** Closing the window keeps the app and its agents running (macOS convention). Quitting stops every agent session and every process group before exit, and the packaged-app proofs check for survivors by pid.

## Testing strategy

- **Unit tests** (`tests/`, vitest, on macOS in CI) for everything pure or local, including stand-in CLIs that die mid-write and conversation files damaged on disk: flag building, both parsers against recorded CLI traffic, the manager with a fake launcher, the guard, the process runner with real child processes, the MCP tools through an in-memory MCP client against real routes.
- **Smokes** (`scripts/smoke-*.ts`) run real CLIs on small models, outside the app.
- **Proof gates** (`scripts/proof-*.ts`) launch the packaged proof build through Playwright's Electron driver with launchd's bare PATH, click through the UI, and check state through the API and by pid. Most use recorded stand-in CLIs and cost nothing. A few run real Haiku or Codex conversations, and `proof:phone` needs real Tailscale. Their headers say which. [The developer guide](user/developer.md#testing-and-proofs) lists them. Screenshots go to `docs/proof/` unless `COCKPIT_PROOF_DIR` says otherwise. Waits poll from Node, because Playwright's `waitForFunction` does not await an async predicate (a Promise is truthy), which once let a gate pass on stale state.

## Setup independence

State defaults to the current operating-system user's home directory; `COCKPIT_HOME` provides explicit isolation for tests. CLI discovery uses that user's login-shell PATH with standard installation fallbacks. Tailscale discovery follows the resolved PATH before standard Mac locations. Tailscale identity is read at runtime; every installation approves and stores its own phone pairing and generates its own Web Push signing keys. A blank model field delegates model selection to the selected CLI's configuration. `npm run doctor` checks local prerequisites without attempting sign-in or running agent turns.
